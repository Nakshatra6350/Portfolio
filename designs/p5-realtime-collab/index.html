Real-time Collaborative Engine

A multi-user collaborative text editor’s backend, built so that several server instances behind one Redis 8 backplane behave like one server. Concurrent edits merge without a lock, a leader or a central transform, because the document is an RGA CRDT in which every insert and delete commutes; a per-document Redis Stream is the durable, sequence-numbered op log that reconnecting clients resume from; pub/sub carries edits between instances; and a presence hash with heartbeat TTLs answers who is here. Around 4,800 lines of dependency-light ESM — ws and redis, no framework, no build step, no bundler.

The one hard problem this project exists to teach

Two people typing into the same document have already diverged by the time either message arrives. Every hard thing in this codebase follows from that one sentence.

The obvious wire format is “insert x at index 5”, and it is wrong the moment two replicas differ by a single character — which is always, because the entire point of optimistic local editing is that a client applies its own keystroke before the server has seen it. Operational transformation rescues indexes by rewriting every operation against every concurrent operation it did not see; that is a correct answer, and it needs a central authority to define what “concurrent” means. A CRDT takes the other road: change the operations until order stops mattering. An insert names the identity of the character it follows ({s: 'alice', c: 7}), never a position. A delete unlinks nothing, it sets a flag. Both are idempotent and commutative, so any two replicas that have seen the same set of operations hold byte-identical documents, in whatever order those operations arrived, with nobody arbitrating.

Be precise about what that buys: freedom from ordering, not freedom from loss. Convergence is conditional on every replica eventually seeing every operation, and Redis pub/sub is fire-and-forget — it drops messages when a subscriber is slow or a connection blips. Sequence numbers, gap detection, a durable Stream to repair from, snapshots for when the repair would be too large, presence sweeps for clients that never said goodbye: all of it exists only to make “eventually sees every operation” true. The CRDT is 565 lines. The delivery machinery around it is the other four thousand, and that ratio is the lesson.

What you will build

One Node process, one port. The HTTP server serves the editor page, /healthz with live per-document statistics, /metrics with counters, and /rga.js — which is src/crdt/rga.js streamed straight to the browser, so client and server run the same merge code rather than two hand-written implementations of one comparator. The same server handles the WebSocket upgrade on /ws. Run two copies of it against one Redis and they behave as a single server; that is the whole claim, and docker-compose.yml exists to let you disprove it.

Follow one keystroke. The client turns it into one RGA op per character, applies it to its own replica immediately, and sends it. The receiving instance appends it to the Redis Stream — which is where its sequence number comes from — applies it to the in-memory document, writes it to every local socket except the author’s (who gets an ack carrying the sequence), and publishes it. The other instance receives the publish, compares the sequence against its own watermark, repairs from the Stream if it finds a gap, applies, and writes to its sockets. Nothing in that path blocks on a lock, and no step needs to know which instance a client is attached to.

No Dockerfile, and that is deliberate

Compose runs the stock node:22-alpine image with the repository bind-mounted at /app and node src/index.js as the command. Both dependencies (ws, redis) are pure JavaScript with no native addon, so a node_modules installed on your host — Windows included — is portable straight into the container; the [ -d node_modules ] || npm install --omit=dev guard in the command only exists so a clean checkout also works. There is no build step to containerise, and skipping the image build keeps make up to a few seconds.

Quick start

Node 22 or newer, and a Redis 8 you can reach — Docker for both, or Docker for Redis and Node on your machine. The unit tests need neither.

cd 10-projects/p5-realtime-collab/code
npm install                      # ws and redis, nothing else

make up                          # docker compose up -d, waits for the redis healthcheck
                                 # app1 -> http://localhost:58080
                                 # app2 -> http://localhost:58081

make logs                        # tail both instances
make down                        # stop the stack and delete the Redis volume

make dev                         # instance A on :58080, INSTANCE_ID=dev-a, node --watch
make dev2                        # instance B on :58081, INSTANCE_ID=dev-b, second terminal

make test                        # everything; integration self-skips with no Redis
make test-unit                   # RGA + Document + protocol, no Redis needed

Two tabs on the same port prove nothing

Open localhost:58080 twice and the edits merge perfectly — and you have tested nothing beyond an in-process broadcast loop. Both sockets live in one registry.js, which writes to every local socket before it ever touches Redis, so you can delete the entire redisBus.js publish and the demo still looks correct. That is exactly why docker-compose.yml brings up two app containers on two host ports. The interesting assertion is always “a client on :58080 sees an edit made on :58081”, and every worthwhile manual test has one tab on each.

A green make test can mean the backplane was never exercised

test/integration.test.js checks whether Redis is reachable and skips if it is not, so make test exits 0 on a machine with no Redis running while never having started a second instance, never having published anything, and never having repaired a gap. Read the summary line, not just the exit code: if the skip count is not zero you ran the CRDT unit tests and called it a pass. make test-integration does not change that — the skip is decided at import time by a Redis probe, whichever script invoked the file — but it runs only that file, so a missing Redis shows up as # pass 0 beside # skipped 1 with nothing green to hide behind. In CI, assert the skip count is zero or gate the job on a Redis service container.

Windows: the Makefile recipes are shell one-liners

Every target is one command, so a machine without make loses nothing — read the recipe and run it. The one thing that does not translate is the inline environment prefix: PORT=58081 node src/index.js is a syntax error in PowerShell, where you want $env:PORT=58081; $env:INSTANCE_ID='dev-b'; node src/index.js. Git Bash and WSL run the Makefile unchanged.
